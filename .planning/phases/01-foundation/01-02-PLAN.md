### Task 1: ProjectResolver Service

**File(s):**
- `src/services/project-resolver.ts`
- `src/config/config-loader.ts`
- `src/config/types.ts`

**Action:** Create the project inference pipeline that maps a working directory to a canonical project.

**`src/config/types.ts`** — Configuration schema:
```typescript
import { z } from 'zod'

export const projectAliasSchema = z.object({
  slug: z.string().regex(/^[a-z0-9-]+$/),
  displayName: z.string(),
  clientName: z.string().optional(),
  hourlyRate: z.number().positive().optional(),
  currency: z.string().default('USD'),
})

export const configSchema = z.object({
  projects: z.record(z.string(), projectAliasSchema).default({}),
  // key = absolute directory path, value = project config
  defaults: z.object({
    currency: z.string().default('USD'),
  }).default({}),
})

export type ProjectAlias = z.infer<typeof projectAliasSchema>
export type Config = z.infer<typeof configSchema>
```

**`src/config/config-loader.ts`** — Reads and writes `~/.tt/config.json`:
- `loadConfig(): Config` — read file, parse with Zod, return defaults if file missing or invalid
- `saveConfig(config: Config): void` — write JSON with 2-space indent
- `addAlias(dirPath: string, alias: ProjectAlias): Config` — immutable update, adds entry to `projects` map
- Config path: `path.join(os.homedir(), '.tt', 'config.json')`
- Auto-create `~/.tt/` if missing
- If config.json exists but fails Zod validation, log a warning and return defaults (do not crash)

**`src/services/project-resolver.ts`** — Resolution pipeline:
```typescript
export interface ResolvedProject {
  slug: string
  displayName: string
  directoryPath: string
  source: 'git' | 'alias' | 'dir' | 'prompt'
  clientName?: string
  hourlyRate?: number
  currency: string
}
```

Resolution order (first match wins):
1. **Alias lookup**: Check `config.projects` for a key matching the absolute path of `cwd` (or any parent). If found, return with `source: 'alias'`.
2. **Git root detection**: Run `git rev-parse --show-toplevel` in `cwd` via `Bun.spawnSync`. If successful:
   - Use `path.basename(gitRoot)` as the slug (lowercased, spaces replaced with hyphens)
   - Use the basename as displayName
   - Return with `source: 'git'`, `directoryPath: gitRoot`
3. **Non-git fallback**: If no git root found and running in a TTY, use `process.stdin` to prompt for project name. If not a TTY (piped/non-interactive), throw with helpful error message.

Exported functions:
- `resolveProject(cwd: string): ResolvedProject` — main resolution function
- `ensureProjectInDb(resolved: ResolvedProject, projectRepo): Project` — find-or-create the project in the database, snapshot rate from config

The function `ensureProjectInDb` should:
- Look up project by `directoryPath` first, then by `slug`
- If found, return existing (do NOT update rate — rate changes are explicit)
- If not found, create with rate from resolved config or `null`

### Task 2: CLI Entry Point with gunshi

**File(s):**
- `src/cli/index.ts`
- `src/cli/commands/version.ts`

**Action:** Create the CLI entry point using gunshi's declarative object-based command syntax with lazy subcommands.

**`src/cli/index.ts`** — Main entry point:
```typescript
#!/usr/bin/env bun
import { cli } from 'gunshi'

// Main command (shown when running `tt` with no subcommand)
const mainCommand = {
  name: 'tt',
  description: 'Time tracking for developers',
  run: async (ctx: any) => {
    // Default behavior: show help
    // gunshi auto-generates help when no run or subcommand matches
  }
}

// Lazy subcommands — only imported when invoked (keeps startup fast)
const subCommands = new Map<string, () => Promise<any>>()
subCommands.set('start', () => import('./commands/start').then(m => m.default))
subCommands.set('stop', () => import('./commands/stop').then(m => m.default))
subCommands.set('now', () => import('./commands/now').then(m => m.default))
subCommands.set('note', () => import('./commands/note').then(m => m.default))
subCommands.set('tag', () => import('./commands/tag').then(m => m.default))

await cli(process.argv.slice(2), mainCommand, {
  name: 'tt',
  version: '0.1.0',
  subCommands,
})
```

**`src/cli/commands/version.ts`** — placeholder (gunshi handles `--version` natively, but keep this for reference):
- gunshi's `cli()` third argument `{ version: '0.1.0' }` auto-handles `--version` and `--help`

**File(s):**

**Action:** Create the build script that produces a compiled `tt` binary.

**`build.ts`:**
```typescript
await Bun.build({
  entrypoints: ['./src/cli/index.ts'],
  outdir: './dist',
  target: 'bun',
  minify: true,
})
// Then compile:
// bun build --compile src/cli/index.ts --outfile dist/tt
```

Actually, `bun build --compile` is a CLI command, not a JS API call. Use a shell script approach:

**Add to `package.json` scripts:**
```json
{
  "scripts": {
    "build": "bun build --compile src/cli/index.ts --outfile dist/tt --minify",
    "dev": "bun run src/cli/index.ts",
    "db:push": "bunx drizzle-kit push"
  }
}
```

After building:
- Verify `dist/tt --version` outputs `0.1.0`
- Verify `dist/tt --help` shows available subcommands
