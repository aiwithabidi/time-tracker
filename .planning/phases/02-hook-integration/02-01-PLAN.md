# Plan 02-01: Shell Hook Scripts and `tt pulse` Subcommand

**Phase:** 02-hook-integration
**Depends on:** Phase 1 complete (schema, repositories, session service, CLI framework)
**Provides:** Activity pulse pipeline from Claude Code hooks → `tt pulse` → SQLite; auto-start on first pulse; rate limiting; shell hook scripts ready for installation

## Goal

When Claude Code fires lifecycle events (SessionStart, PostToolUse, Stop), thin shell scripts call `tt pulse` which writes a rate-limited activity heartbeat to SQLite. If no active session exists for the project, one is auto-created. This is the core pipeline that enables automatic time tracking.

## Requirements Covered

- **AUTO-01**: SessionStart hook auto-starts/attaches session
- **AUTO-02**: Stop hook fires final pulse
- **AUTO-03**: Hook scripts execute in <100ms (async hooks + compiled binary)
- **AUTO-04**: Activity pulses on tool use, rate-limited 1/60s per terminal
- **AUTO-05**: Sessions use heartbeat-based lifecycle (hooks are fire-and-forget)
- **AUTO-06**: Stale sessions auto-closed on next startup (reconciliation)

### Task 2: `tt pulse` command — core heartbeat handler

Create the `tt pulse` subcommand that receives hook signals, rate-limits writes, auto-starts sessions, and records activity pulses.

**Files:**
- `src/cli/commands/pulse.ts` — New command handler
- `src/cli/index.ts` — Register `pulse` subcommand
- `src/core/session/session-service.ts` — Add `pulse()` method

**Command interface:**
```
tt pulse --source <source> --cwd <dir> [--session-id <id>] [--terminal-id <id>]
```

**Arguments:**
- `--source` (required): Hook source — `claude-startup`, `claude-resume`, `post-tool-use`, `stop`, `manual`
- `--cwd` (required): Working directory for project inference
- `--session-id` (optional): Claude session ID for correlation
- `--terminal-id` (optional): Override TT_TERMINAL_ID env var

**Implementation — `pulse()` method on session service:**

1. **Resolve terminal ID**: `--terminal-id` flag > `TT_TERMINAL_ID` env > `pid-{process.pid}`
2. **Rate limit check**: Query latest pulse for this terminal via `getLatestForTerminal(terminalId)`. Compare `lastPulse.timestamp` (not `createdAt` — schema column is `timestamp`) against `Date.now()`. If within 60 seconds, exit silently (return early, no error)
3. **Resolve project**: Use ProjectResolver with `--cwd` (same as `tt start`)
4. **Find active session**: `findActiveByProject(projectId)`
5. **If no active session**: Auto-create one (source from `--source` flag, e.g. `hook-post-tool-use`). Attach terminal. This handles SessionStart unreliability.
6. **If active session exists**: Attach terminal if not already attached (idempotent)
7. **Write pulse**: Insert into `activity_pulses` with sessionId, terminalId, sourceType, timestamp
8. **Startup reconciliation**: Before step 4, check for any stale sessions across all projects and auto-close them (reuse existing `closeStaleSession` logic)

**Command handler (`pulse.ts`):**
- Silent on success (no output — called by hooks, not humans)
- Exit 0 always (hooks should never fail visibly)
- Wrap entire handler in try/catch — swallow all errors with exit 0

**Acceptance:**
- `tt pulse --source manual --cwd /path/to/project` writes a pulse
- Running twice within 60s writes only one pulse (rate limiting)
- Running with no active session auto-creates one
- Running with an active session in a different terminal attaches to it
- Stale sessions from previous days are auto-closed

### Task 3: Shell hook scripts

Create the three shell scripts that Claude Code hooks will execute.

**Files:**
- `src/hooks/session-start.sh` — SessionStart hook
- `src/hooks/post-tool-use.sh` — PostToolUse hook (heartbeat)
- `src/hooks/stop.sh` — Stop hook (final pulse)

**All scripts share this pattern:**
```bash
#!/bin/bash
INPUT=$(cat)  # Always consume stdin
# Extract fields with jq
# Call tt pulse with appropriate --source
# Suppress errors, exit 0
```

**Terminal ID persistence across hooks:**

Each hook invocation is a fresh shell process — env vars and PIDs differ every time. To maintain a stable terminal ID for rate limiting and terminal attachment:

1. `session-start.sh` generates a stable terminal ID and writes it to `~/.tt/terminals/{claude_session_id}`
2. `post-tool-use.sh` and `stop.sh` read the terminal ID from the file for that Claude session
3. If the file doesn't exist (SessionStart didn't fire — known bug #10373), fall back to `TT_TERMINAL_ID` env var, then `unknown-{claude_session_id}`

**session-start.sh:**
```bash
#!/bin/bash
INPUT=$(cat)
SESSION_ID=$(echo "$INPUT" | jq -r '.session_id // ""')
CWD=$(echo "$INPUT" | jq -r '.cwd // "."')
SOURCE=$(echo "$INPUT" | jq -r '.source // "startup"')

# Generate stable terminal ID for this Claude session
TERMINAL_ID="${TT_TERMINAL_ID:-tt-$(echo "$SESSION_ID" | head -c 12)}"

# Persist for subsequent hooks
mkdir -p ~/.tt/terminals
echo "$TERMINAL_ID" > ~/.tt/terminals/"$SESSION_ID"

~/.tt/bin/tt pulse \
  --source "claude-${SOURCE}" \
  --session-id "$SESSION_ID" \
  --terminal-id "$TERMINAL_ID" \
  --cwd "$CWD" \
  2>/dev/null

exit 0
```

**post-tool-use.sh:**
```bash
#!/bin/bash
INPUT=$(cat)
SESSION_ID=$(echo "$INPUT" | jq -r '.session_id // ""')
CWD=$(echo "$INPUT" | jq -r '.cwd // "."')

# Read persistent terminal ID (written by session-start.sh)
TERMINAL_ID=$(cat ~/.tt/terminals/"$SESSION_ID" 2>/dev/null || echo "${TT_TERMINAL_ID:-unknown-${SESSION_ID:0:12}}")

exec ~/.tt/bin/tt pulse \
  --source "post-tool-use" \
  --session-id "$SESSION_ID" \
  --terminal-id "$TERMINAL_ID" \
  --cwd "$CWD" \
  2>/dev/null || true
```
Note: Uses `exec` to replace shell process (one fewer process layer). `|| true` ensures exit 0 even if binary fails.

**stop.sh:**
```bash
#!/bin/bash
INPUT=$(cat)

# Prevent infinite loop
if [ "$(echo "$INPUT" | jq -r '.stop_hook_active')" = "true" ]; then
  exit 0
fi

SESSION_ID=$(echo "$INPUT" | jq -r '.session_id // ""')
CWD=$(echo "$INPUT" | jq -r '.cwd // "."')
TERMINAL_ID=$(cat ~/.tt/terminals/"$SESSION_ID" 2>/dev/null || echo "${TT_TERMINAL_ID:-unknown-${SESSION_ID:0:12}}")

exec ~/.tt/bin/tt pulse \
  --source "stop" \
  --session-id "$SESSION_ID" \
  --terminal-id "$TERMINAL_ID" \
  --cwd "$CWD" \
  2>/dev/null || true
```

**Acceptance:**
- All scripts are executable (`chmod +x`)
- All scripts consume stdin before doing anything
- session-start.sh writes terminal ID to `~/.tt/terminals/{session_id}`
- post-tool-use.sh and stop.sh read terminal ID from file, with fallback chain
- stop.sh checks `stop_hook_active` and exits early if true
- Scripts use absolute path to tt binary at `~/.tt/bin/tt`
- All scripts exit 0 regardless of tt binary success/failure
- Rate limiting works because terminal ID is stable across all hooks for the same Claude session

### Task 4: `tt setup` command

Create a setup command that writes hook scripts to `~/.tt/hooks/`, creates the `~/.tt/terminals/` directory, and prints the exact settings.json configuration for the user.

Note: Uses flat `tt setup` command (not nested `tt hooks install`) to match existing gunshi registration pattern in `cli/index.ts`.

**Files:**
- `src/cli/commands/setup.ts` — New command handler
- `src/cli/index.ts` — Register `setup` subcommand (flat, same pattern as `start`/`stop`)

**Implementation:**
1. Create `~/.tt/hooks/` and `~/.tt/terminals/` directories
2. Write the three hook scripts directly as string literals (simpler for compiled binary than bundling files)
3. `chmod +x` all scripts via `fs.chmodSync(path, 0o755)`
4. Also create `~/.tt/bin/` directory and symlink the current binary (or instruct user to copy)
5. Print the exact settings.json hook configuration to stdout:

```
Hook scripts installed to ~/.tt/hooks/

Add the following to your ~/.claude/settings.json "hooks" section:

"SessionStart": [
  {
    "matcher": "startup",
    "hooks": [{
      "type": "command",
      "command": "~/.tt/hooks/session-start.sh",
      "timeout": 10
    }]
  },
  {
    "matcher": "resume",
    "hooks": [{
      "type": "command",
      "command": "~/.tt/hooks/session-start.sh",
      "timeout": 10
    }]
  }
],
"PostToolUse": [
  {
    "hooks": [{
      "type": "command",
      "command": "~/.tt/hooks/post-tool-use.sh",
      "async": true,
      "timeout": 5
    }]
  }
],
"Stop": [
  {
    "hooks": [{
      "type": "command",
      "command": "~/.tt/hooks/stop.sh",
      "async": true,
      "timeout": 5
    }]
  }
]

Then restart Claude Code to activate hooks.
```

Note the critical `"async": true` on PostToolUse and Stop hooks — this ensures hooks never block Claude (AUTO-03).

**Acceptance:**
- Running `tt setup` creates `~/.tt/hooks/` with all 3 scripts
- Creates `~/.tt/terminals/` directory for terminal ID persistence
- Scripts are executable (mode 755)
- Output shows exact JSON including `async: true` on PostToolUse and Stop
- Running twice is idempotent (overwrites existing scripts)

## Risks

- **jq dependency**: Hook scripts require `jq` to be installed. macOS ships with it via Xcode command line tools, but should document as a prerequisite.
- **Binary path**: Scripts reference `~/.tt/bin/tt` — the `hooks install` command must ensure the binary exists there. For development, use `bun run dev` path instead.
- **Compiled binary includes hooks**: When using `bun build --compile`, the hook script content must be either bundled as strings or written by the install command.
