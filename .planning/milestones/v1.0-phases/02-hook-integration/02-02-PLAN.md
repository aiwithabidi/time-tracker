# Plan 02-02: IdleDetector, `tt away`/`tt back`, and Startup Reconciliation

**Phase:** 02-hook-integration
**Depends on:** Plan 02-01 (pulse command, schema migration with `pausedAt`)
**Provides:** Idle detection with auto-pause/resume, intentional break commands, robust startup reconciliation, idle state displayed in `tt now`

## Goal

Leaving a terminal idle for 20 minutes auto-pauses the session so idle time doesn't count toward billing. Resuming activity auto-resumes tracking. Users can also declare intentional breaks with `tt away`/`tt back`. The system handles all edge cases: crashes, force-quits, overnight abandonment.

## Requirements Covered

- **IDLE-01**: Soft idle at ~8 minutes with no pulses (displayed in `tt now`)
- **IDLE-02**: Hard auto-pause at ~20 minutes with no pulses
- **IDLE-03**: Auto-resume on next activity pulse (no manual action)
- **IDLE-04**: Idle time tracked in `idle_deducted_ms`
- **IDLE-05**: `tt away` and `tt back` for intentional breaks

## Tasks

### Task 1: IdleDetector — pure stateless computation

Create the IdleDetector module as a pure function with no I/O. It receives timestamps and config, returns idle state.

**Files:**
- `src/core/session/idle-detector.ts` — New module

**Interface:**
```typescript
type IdleState = 'active' | 'soft-idle' | 'hard-idle' | 'paused'

interface IdleConfig {
  readonly softIdleMs: number   // default: 8 * 60 * 1000 (8 min)
  readonly hardIdleMs: number   // default: 20 * 60 * 1000 (20 min)
}

function computeIdleState(
  lastPulseAt: number,
  nowMs: number,
  pausedAt: number | null,
  config: IdleConfig,
): IdleState

function computeIdleDeduction(
  lastPulseAt: number,
  nowMs: number,
  config: IdleConfig,
): number  // milliseconds to deduct
```

**Logic for `computeIdleState`:**
1. If `pausedAt` is not null → return `'paused'` (intentional break via `tt away`)
2. Compute `elapsed = nowMs - lastPulseAt`
3. If `elapsed >= hardIdleMs` → return `'hard-idle'`
4. If `elapsed >= softIdleMs` → return `'soft-idle'`
5. Otherwise → return `'active'`

**Logic for `computeIdleDeduction`:**

Formula: `Math.max(0, elapsed - softIdleMs)` where `elapsed = nowMs - lastPulseAt`

Rationale: The soft idle threshold (8 min) acts as a grace period. If the user was idle for 25 minutes, they were probably still working for the first ~8 minutes after the last pulse (just not using Claude Code tools). Deducting only the time beyond the grace period is the most generous, defensible approach for billing.

1. Compute `elapsed = nowMs - lastPulseAt`
2. If `elapsed < hardIdleMs` → return 0 (no deduction needed — not yet hard-idle)
3. Return `Math.max(0, elapsed - softIdleMs)` — deduct time beyond the grace period

**Example with defaults (8min soft, 20min hard):**
- 25-minute gap: deduction = 25 - 8 = **17 minutes** (user gets credit for first 8 min)
- 60-minute gap: deduction = 60 - 8 = **52 minutes**
- 15-minute gap: deduction = **0** (not yet hard-idle at 20min threshold)
- 8-minute gap: deduction = **0** (soft-idle only, no deduction)

**Acceptance:**
- `computeIdleState` returns correct state for all threshold boundaries
- `computeIdleDeduction(lastPulse, lastPulse + 25*60*1000, {softIdleMs: 8*60*1000, hardIdleMs: 20*60*1000})` returns `17 * 60 * 1000`
- `computeIdleDeduction` returns 0 for gaps shorter than hardIdleMs
- Module has no imports except types — fully unit-testable
- Default config exported as `DEFAULT_IDLE_CONFIG`

### Task 2: Integrate idle detection into `tt pulse`

Update the pulse flow to check idle state and auto-pause/resume sessions.

**Files:**
- `src/core/session/session-service.ts` — Update `pulse()` method from Plan 02-01
- `src/db/repositories/session-repository.ts` — Add `resumeFromIdle(id, deductionMs)` method

**New repository method — `resumeFromIdle`:**
```typescript
resumeFromIdle(id: string, deductionMs: number): Session {
  // Atomic: add to idle_deducted_ms AND clear paused_at in one statement
  // SQL: UPDATE sessions SET idle_deducted_ms = idle_deducted_ms + ?, paused_at = NULL, updated_at = ? WHERE id = ?
  db.update(sessions)
    .set({
      idleDeductedMs: sql`${sessions.idleDeductedMs} + ${deductionMs}`,
      pausedAt: null,
      updatedAt: Date.now(),
    })
    .where(eq(sessions.id, id))
    .run()
  // Return fresh select
}
```

**Updated pulse flow (after rate limit check and project resolution):**

1. Find active session for project
2. If no active session → auto-create (existing from 02-01)
3. If active session exists:
   a. Get latest pulse for this session
   b. Compute idle state via `computeIdleState(lastPulse.timestamp, now, session.pausedAt, config)`
   c. If `'hard-idle'`:
      - Compute deduction: `computeIdleDeduction(lastPulse.timestamp, now, config)`
      - Update session: `idleDeductedMs += deduction`, clear `pausedAt` if set
      - This effectively auto-pauses and immediately auto-resumes
   d. If `'paused'` (was away):
      - Compute deduction: `now - session.pausedAt`
      - Update session: `idleDeductedMs += deduction`, clear `pausedAt`
      - Auto-resume from intentional break
4. Attach terminal if not attached
5. Write pulse

**New repository method needed:**
- `sessions.updateIdleDeduction(id, additionalMs)` — atomically adds to `idle_deducted_ms` and clears `paused_at`
- Or: `sessions.resumeFromIdle(id, deductionMs)` — adds to idle_deducted_ms, clears paused_at, sets updatedAt

**Acceptance:**
- Pulse after 25min gap deducts ~25min from session duration
- Pulse while away (pausedAt set) resumes and deducts break time
- Pulse while active does nothing special (just writes pulse)
- `tt now` shows corrected duration (subtracts idleDeductedMs)

**New repository method — `setPausedAt`:**
```typescript
setPausedAt(id: string, pausedAt: number | null): Session {
  // SQL: UPDATE sessions SET paused_at = ?, updated_at = ? WHERE id = ?
  db.update(sessions)
    .set({ pausedAt, updatedAt: Date.now() })
    .where(eq(sessions.id, id))
    .run()
  // Return fresh select
}
```

**`tt away` behavior:**
1. Find active session for current project (same resolution as `tt now`)
2. If no active session → error: "No active session to pause"
3. If already paused → show current pause status: "Already on break (15m so far)"
4. Set `pausedAt = Date.now()` on the session
5. Output: `◎ Taking a break from time-tracker`

**`tt back` behavior:**
1. Find active session that has `pausedAt` set
2. If no paused session → error: "Not on a break. Try 'tt away' first"
3. Compute break duration: `now - pausedAt`
4. Update session: `idleDeductedMs += breakDuration`, clear `pausedAt`
5. Write a pulse (resume activity)
6. Output: `▶ Back on time-tracker — 15m break deducted`

**Session service methods:**
```typescript
away(cwd: string): { session: Session; project: Project }
back(cwd: string, terminalId: string): { session: Session; project: Project; breakDurationMs: number }
```

**Acceptance:**
- `tt away` → `tt back` correctly deducts break time
- `tt away` while already away shows friendly status
- `tt back` when not away shows helpful error
- Pulse arriving while away auto-resumes (from Task 2)
- `tt now` shows "(on break — 15m)" when paused

## Risks

- **Simulated time in tests**: Unit tests need to control `Date.now()` to test idle thresholds. Use dependency injection (pass `now` as parameter to computeIdleState) rather than mocking globals.
- **Race condition**: Two simultaneous pulses from different terminals could both compute idle deduction. Mitigated by SQLite's single-writer lock and atomic update (`idle_deducted_ms = idle_deducted_ms + ?`).
- **Clock skew**: If system clock changes between pulses, idle detection could produce negative values. Use `Math.max(0, deduction)` as a guard.
